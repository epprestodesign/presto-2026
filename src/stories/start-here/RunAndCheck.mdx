<div className="sh-section">
  <h2 className="sh-h2" id="check">Check</h2>
  <p className="sh-sub">Three checks. Run them before you open a pull request.</p>
  <div className="sh-steps">
    <div className="sh-step">
      <span className="sh-step__n">1</span>
      <div className="sh-step__title">Accessibility</div>
      <div className="sh-step__text">Run <code>pnpm build-storybook</code>, then <code>pnpm a11y:ci</code>. It checks every story against WCAG 2.2 A and AA with axe. To read the result by rule, save the log with <code>pnpm a11y:ci &gt; a11y.log 2&gt;&amp;1</code>, then run <code>node scripts/a11y-report.mjs a11y.log</code>. In CI, <code>a11y.yml</code> runs the same check on every pull request to <code>main</code>. It reports problems but does not fail the run, unless you start it by hand with strict turned on.</div>
    </div>
    <div className="sh-step">
      <span className="sh-step__n">2</span>
      <div className="sh-step__title">Links</div>
      <div className="sh-step__text">Run <code>node scripts/check-story-links.mjs</code> after a build, or add <code>http://127.0.0.1:6006</code> to check a running Storybook. It compares every story id from before the reorganisation with today's index. It fails if an old id is neither kept nor redirected, if a redirect points nowhere, or if a link on a docs page is broken.</div>
    </div>
    <div className="sh-step">
      <span className="sh-step__n">3</span>
      <div className="sh-step__title">Docs screenshots</div>
      <div className="sh-step__text">With the Storybook running, run <code>node scripts/capture-docs-screens.mjs</code>. It captures live stories at 1440 by 900 and saves them to <code>src/stories/start-here/screens/</code>. Run it when a page shown on these docs changes.</div>
    </div>
  </div>
</div>

<div className="sh-section">
  <h2 className="sh-h2" id="add-a-part">Add a part</h2>
  <p className="sh-sub">Five steps, so a new part lands in the right place and its link never breaks.</p>
  <div className="sh-steps">
    <div className="sh-step">
      <span className="sh-step__n">1</span>
      <div className="sh-step__title">Choose the area by its rule</div>
      <div className="sh-step__text">Each area has a one-line rule. Pick the one that fits. <Go page="Start Here/How to browse" className="sh-link">The rules</Go></div>
    </div>
    <div className="sh-step">
      <span className="sh-step__n">2</span>
      <div className="sh-step__title">Give it a title</div>
      <div className="sh-step__text">The title is its place in the sidebar, for example <code>title: 'Edge Cases/Cart/Cart Flyout'</code>.</div>
    </div>
    <div className="sh-step">
      <span className="sh-step__n">3</span>
      <div className="sh-step__title">Pin its id</div>
      <div className="sh-step__text">In a new file, set <code>id:</code> to the title in lower case with dashes: <code>id: 'edge-cases-cart-cart-flyout'</code>. The link then stays the same if the title moves later. Never change the <code>id:</code> of a file that already has one.</div>
    </div>
    <div className="sh-step">
      <span className="sh-step__n">4</span>
      <div className="sh-step__title">Add it to the sidebar order</div>
      <div className="sh-step__text">Add the title to <code>storySort</code> in <code>.storybook/preview.js</code>, in the spot where it belongs.</div>
    </div>
    <div className="sh-step">
      <span className="sh-step__n">5</span>
      <div className="sh-step__title">Redirect a renamed docs page</div>
      <div className="sh-step__text">A docs page's id comes from its title. If you rename one that has been shared, add a <code>MOVED</code> entry in <code>.storybook/manager.js</code> from the old id to the new page, then run the link check.</div>
    </div>
  </div>
</div>

<div className="sh-section">
  <h2 className="sh-h2" id="deploy">Deploy</h2>
  <p className="sh-sub">Merge to <code>main</code> and it deploys. Work on a branch, never on <code>main</code>.</p>
  <ul className="sh-list">
    <li><code>deploy.yml</code> runs on every push to <code>main</code>. You can also start it by hand.</li>
    <li>It installs with pnpm 9 on Node 24, then runs <code>pnpm build-storybook</code>.</li>
    <li>It builds each prototype with Vite and copies it into the Storybook build, so each one is served from its own folder under <code>/presto-2026/</code>.</li>
    <li>The builds use the shared imagery library and a Google Maps key kept as a repo secret.</li>
    <li>It uploads the result and deploys it to GitHub Pages. Only one deploy runs at a time, and a newer push cancels one in progress.</li>
  </ul>
</div>
